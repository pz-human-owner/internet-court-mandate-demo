Partner settlement: MetaMask delegation

The verdict above also decides a payment. Using the MetaMask Smart Accounts Kit (an ERC-7710 delegation), the principal's MetaMask smart account on Ethereum Sepolia lets a settlement account, the clerk, pay the agent, but only in one exact way.

Live on Sepolia: verdict TRUE → agent paid 0.001 ETH

  1. 1 · GrantThe principal signs one delegation to the clerk: “pay the agent exactly 0.001 ETH, once, before expiry.” This is an off-chain signature, not a transaction.
  2. 2 · Verdict TRUE → paidThe clerk reads get_verdict from this GenLayer contract. On a resolved TRUE it redeems the delegation through MetaMask's DelegationManager, and the agent receives 0.001 ETH.
  3. 3 · FALSE or UNDETERMINED → refusedThe clerk does not redeem, and the delegation lapses at its expiry. An unresolved case waits.

Limits checked on-chain by MetaMask's Delegation Framework

  • Spending cap: at most the 0.001 ETH fee, in total (nativeTokenTransferAmount)
  • Exact payment: the only allowed call sends exactly the fee to the named agent (exactExecution)
  • Clerk only: no other account can redeem (redeemer)
  • Once: a single redemption (limitedCalls)
  • Expiry: only before a deadline (timestamp; the live run used 7 days)

What this does not prove

  • The clerk is trusted. GenLayer and Sepolia have no oracle between them, so the clerk's code checks the verdict and the case label (a salt derived from GenLayer chain 4221 + this contract). No contract checks them on Sepolia.
  • It isn't an escrow. The fee sits in the principal's own smart account, and the owner could move it out before redemption.
  • One operator. The same operator held the throwaway owner and clerk keys, and the clerk paid the gas and funded the fee for the demo.
  • Simulated only: the FALSE path and the on-chain rejections (an outsider, a second redemption, a redemption after expiry), on a local Sepolia fork.
